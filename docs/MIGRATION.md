# تقرير ترقية بيانات الحوت

الترقية توسعية وآمنة: تنشئ ورقة `contracts`، وتضيف `contract_id` و`paid_after` و`remaining_after` إلى `payments`، وتبقي الأعمدة القديمة دون حذف. منطق Phase 1 لا يقرأ البيانات المالية القديمة من `customers`؛ كل عقد جديد مستقل وتُجمع دفعاته بفهرس `paymentsByContract`.

البيانات الحالية تجريبية، لذلك لا تُنشأ Migration تلقائية من صفوف العملاء القديمة إلى عقود. بعد النسخ الاحتياطي يمكن إنشاء بيانات اختبار جديدة للعقود المتعددة.

قبل التنفيذ المادي، تنشئ `applySheetsUpgrade()` أوراق Backup مؤرخة وتسجل خطة التغيير في `migration_report`. استخدم `upgradeSheets()` أولًا لمعاينة الخطة دون كتابة. راجع [دليل Apps Script](../google-apps-script/README.md) للتشغيل والنشر والرجوع.
